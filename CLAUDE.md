# CLAUDE.md: Aggregate entitlement lab

Tier: Tester. See how an MCP aggregate lists only the tools each caller may use and refuses the rest by name: the six checks, guided steps, a diagram. **Mock** simulates the Ping release claim (2026-11-02, UNVERIFIED on our tenant); **Real** measures your own gateway's aggregate apps with your agent keys. Repo: https://github.com/curtismu7/aggregate-entitlement-LAB, a fork of curtismu7/mcp-tools-LAB (its Entitled listing page). Read `README.md` and `docs/security.md` first; the rulebook is `~/Development/STANDALONE-RULES.md` (skill `standalone-demo`).

## Run and test
- Needs Node 26 or newer. `npm install`, `npm run doctor`, `npm test` (server `node:test`, web vitest, the forbidden-strings gate test and the pin tests), `npm run build`, then `npm start` (`127.0.0.1:7802`, `PORT` to change; there is no dev server, so no second port). Docker: `HOST_PORT=7802 docker compose up --build -d` publishes `127.0.0.1` only. Run suites on the Air (`air-test`), not on this Mac.
- `GET /api/health` answers `demo-health/1` for the shelf.

## Rules that bite (each has a test; do not weaken)
- Binds `127.0.0.1` (`AGG_ENT_BIND` opts in); a loopback `Host` (or `LAB_ALLOWED_HOSTS`) and a same-origin `Origin` on every write. An agent key is never returned, logged or shown; every gateway message is scrubbed of all keys.
- Real (`server/src/gateway/real.js`): settings `AGG_ENT_GW_URL`, `AGG_ENT_GW_APPS`, `AGG_ENT_GW_KEY_<NAME>` from the environment, `STANDALONE_ENV` or `~/Development/.env`. It lists tools, and calls ONLY a name that is not in the caller's listing, with no arguments and an explicit confirm. A listed tool is never called from here. Which of the six checks a refusal matches is our reading; say so.
- Rule 19: `POST /api/mode` takes exactly `{source}`; `GET /api/info` answers `{source, realAvailable, realReason}`; Real not configured is 409 with the how-to and an aria-disabled button with that tooltip; the default is Real only when it is configured. There is no hosted mode.
- The simulated gateway's credential check (`server/src/gateway/`) must never echo a submitted credential; a change there needs the documented limits in `docs/security.md` kept true.
- The diagram is data: `diagrams/gateway.json` (diagram-studio/1) loaded by name; do not hand-build nodes or edges.
- UI: the vendored `web/src/standalone-ui.css` must stay byte-identical to `~/Development/AI-DEMO-Standalone/shared/standalone-ui.css` (`scripts/check-ui-standard.sh`); no local colour literals, no `prefers-color-scheme` outside it, no `!important`. Run `check-css.sh` and `check-drift.sh` from the parent repo before a PR.
- What Privilege did (Rule 25, owner 2026-11-15): the Entitled listing page draws the shared `GatewayTrace` under the call result in Mock (`Gateway.jsx`: step 1 the `tools/list`, step 2 the `tools/call`) and under the Real controls (`GatewayReal.jsx`: one `tools/list` per app, then the listing before a hidden-name call and the call). The panel (`web/src/gateway-trace/*`) and `server/src/gatewayTrace.js` are vendored byte for byte from AI-DEMO-Standalone `shared/gateway-trace/`, pinned by `web/src/gateway-trace/gateway-trace.sha256` and `scripts/gateway-trace.test.mjs`, and never edited here; re-vendor with cp, then re-pin. The lab's own builder is `server/src/gateway/aggregateTrace.js`. HONESTY RULE: Mock (`sim.js`) computed the checks, so those decisions are `checked`; the request is synthetic JSON-RPC to a `.invalid` host and the reply is what the simulation returned (no socket is opened). Real goes through this lab's own MCP client: `createHttpClient({ capture })` in `server/src/mcp/http.js` records each exchange, and `traceFromDoor` turns it into a trace whose decisions are only `inferred` or `observed`, never `checked` (a refusal's check is still only our reading). The trace holds the agent key only as its length, the MCP session id shortened, response headers from an allowlist, and every string is scrubbed of every configured key. Tests: `server/test/gateway-trace.test.js`, `web/src/pages/__tests__/gateway-trace.page.test.jsx`. Real mode against a live gateway is owner-run and UNVERIFIED; the tests use a loopback stub.
- What each layer logged for this run (rule 27, owner 2026-11-22): the shared run-observability panel (`web/src/run-observability/*` and `server/src/runObservability.js`, vendored byte for byte from AI-DEMO-Standalone `shared/run-observability/`, pinned by `web/src/run-observability/run-observability.sha256` and `scripts/run-observability.pin.test.mjs`; re-vendor with `git show origin/main:`, then re-pin; never edit). This lab reads no logs, so it vendors the core only, has no run-observability environment variable and mounts no Docker socket (a test pins all three; the one vendored file that names the reader settings in its own message is skipped by EXACT path). The lab's mapping is ONE file, `server/src/runObs.js`, with the page wrapper `web/src/components/RunObs.jsx`; the route is `GET /api/gateway/run?runId=` (the id a `list`, `call`, `real/list` or `real/call` answer carries in `run: { id }`). A run is one request; Mock rows are the steps `sim.js` computed (policy decisions are Privilege rows, a member's state is an information row in Resource server, the aggregate's answer to a call is information), Real rows are `response` rows stamped with the time of the reply (start plus the call's own ms, never after the session close), and the lab's reading of a refusal is words on that row, never a Privilege row. Stdout lines use none of the words the shared matchers read; a test runs every line kind and a hostile caller through `classify()` for every product. Never-repeat: a row message over 300 characters is cut by the panel (a test checks the longest); a validation failure begins no run (`run: null`).
- Product claims about the Ping release are simulated and UNVERIFIED on our tenant; say so. Never say "door" (say P1 Privilege Agent App).
- The forbidden-strings gate (`npm run check:forbidden`, CI job `forbidden-strings`, secret `FORBIDDEN_STRINGS`) prints counts only. CI is GitHub-hosted, Node 26 only. Docker is OrbStack, never Docker Desktop.
- No AI attribution anywhere (owner, 2026-11-07): no Co-Authored-By trailer and no "Generated with" line in commits, PR bodies or files; CI runs `scripts/check-no-ai-attribution.sh`.
